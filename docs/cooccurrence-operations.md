# 精确共同构成：发布与运维

## 当前实现

分享页按钮首次点击请求 `/api/subjects/related?kind=game&subjectId=12596`，随后展开/收起复用组件内结果。线上查询只读取统计状态、最多 80 字节的前十名，以及最多十个作品身份和名称；不读取完整计数向量，不写 D1。统计尚未就绪返回 503，界面允许重试，不返回虚假的零结果。

同一分享的同类作品 ID 先去重。每个不同作品对在该分享中贡献一次；不是独立人数。所有外部 ID 保持字符串。内部 ID 为不会删除/复用的 uint32，向量按内部 ID 升序排列；每项为小端 uint32 ID + uint32 次数。前十名按次数降序、内部 ID 升序。所有曾共现的候选都保留，下降/删除后可以正确补位。计数溢出、负值或超过 D1 单行容量时停止更新，必须升级存储格式。

`0004_cooccurrence.sql` 只创建四张空表、一条作品唯一索引和注册表触发器，不扫描历史事实表。触发器把旧/新作品集合和旧/新分享身份同原事务写入单调 AUTOINCREMENT 日志。评论变化不会产生统计事件。REPLACE/冲突式导入及直接 rowid 修改会把统计标为无效，阻止继续读取/维护；运维不得绕过触发器重建注册表。

## 日常更新

生产增加 `*/10 * * * *` 调度；测试环境仍无 cron。每日北京时间日期变化时固定一个日志上界，之后的小调用只续跑这一日的工作。空闲调用只读一行控制状态。正常日约 473 份新增分享，不会反复启动新统计窗口。

每个窗口最多 2,000 个事件，超过时拆分追赶。准备阶段先持久化作品身份，再合并增量，按作品整数主键写任务；重复准备使用同一窗口、`ON CONFLICT DO NOTHING`，不会重复累加。工作阶段每次最多更新 180 部作品，每部作品只加载一次完整向量。计数、前十名、作品水位与任务删除在同一 D1 batch 事务提交。全窗口任务完成后才推进全局水位。

控制行保存 120 秒租约，每一小批续租。所有写入都校验租约所有者；失去租约的旧调用不能覆盖新调用结果。已完成且超过七天的日志按主键限量清理；未处理日志永不因年龄删除。重试有调用次数、事件数、作品数的边界，没有无限循环。异常记录在 Workers Logs；不得把统计标为就绪来掩盖异常。

调度每天 144 次，约 4,320 请求/月；空闲时约 4,000 个额外 D1 控制行读取/月，仍包含在既有 100 万后台读取预算中。正常新增量下，每日受影响作品只合并一次。突发积压超过 2,000 个事件时同一作品可能在不同窗口再次合并，费用需按实际日志核算，不能继续声称固定的日均模型是无条件上限。

## 首次初始化

生产写凭据使用临时 `MY9_SQL_MIGRATION_TOKEN`，读取仍使用 `MY9_SQL_API_TOKEN`；完成后移除临时凭据。当前部署请求已批准的预算为 200 万读取、60 万写入、新增物理空间 1 GB。预计约 23.9 万作品行 + 23.9 万唯一索引项；没有千万级事实表写入。

1. 在 Linux/WSL2 或 Linux CI 完成 `npm run lint`、TypeScript 检查、`npm run cf:build`。
2. 设置 `MY9_COOCCURRENCE_DB_ID`，生产值为 `6953e552-443b-479d-b6fa-3ffdeac2e60a`。所有产物保存到仓库之外的绝对目录，不提交分享身份/原始数据。
3. `node scripts/cooccurrence-bootstrap.mjs migrate ABSOLUTE_DIRECTORY` 安装空表与原子日志，并在同一事务登记迁移。该命令仅处理未执行的 `0004`；针对远端 SQL 解析器规范化注释与换行，避免原文直接提交的 `incomplete input` 错误。
4. `node scripts/cooccurrence-bootstrap.mjs scan ABSOLUTE_DIRECTORY`。同一查询获取 H0 与 rowid 上界，按 4,000 行投影扫描 kind/分享身份/九个 ID；保存可恢复分页，然后读取 H0 到 H1 的边界事件。
5. `python scripts/cooccurrence-aggregate.py ABSOLUTE_DIRECTORY`（需要 NumPy）。对扫描期间改变的分享，第一条事件的旧像恢复 H0；H0 后新增的分享排除。覆盖删除、删除后重建、分享身份修改。离线按连续作品 ID 分区计算完整精确计数，输出每批至多 100 行/1 MiB 二进制数据的导入文件。该脚本不访问网络。
6. 临时部署 `scripts/cooccurrence-import-worker.ts`，只绑定目标 D1，并设置随机、短期 `IMPORT_TOKEN` secret。该 Worker 没有任意 SQL 接口，参数化绑定 BLOB。禁止向主站加公共管理入口。
7. 设置 `MY9_COOCCURRENCE_IMPORT_URL` 和 `MY9_COOCCURRENCE_IMPORT_TOKEN`，运行 `node scripts/cooccurrence-bootstrap.mjs import ABSOLUTE_DIRECTORY`。每批身份严格连续，批次哈希和已导入 ID 原子提交，网络结果不确定时可安全恢复。最多五批合并一次 HTTP 往返（请求体最多 8 MB），每个数据库事务仍至多 100 行/1 MiB，单次调用最多 515 个 D1 语句；减少网络等待，不增加写入量。全局 ready 始终为 0。需要使用现有代理访问 workers.dev 时，Node 24 可设置 `NODE_USE_ENV_PROXY=1`。
8. `node scripts/cooccurrence-bootstrap.mjs verify ABSOLUTE_DIRECTORY` 检查作品数、匹配分享总次数、完整向量总字节/最大字节、每行水位及就绪数量。另以已知作品核对排名及最新 D1 物理空间，确认新增不超过 1 GB。
9. `node scripts/cooccurrence-bootstrap.mjs publish ABSOLUTE_DIRECTORY` 只切换一行全局发布状态，不重写全部作品行。部署主站 Worker，后台从 H0 后的事件开始追赶。历史基线可立即查询，并显示对应更新时间。
10. 核对线上 HTTP 返回、已知作品排名、增量任务水位和 Workers 错误。删除临时 importer Worker 及 secret，恢复本地 SQL 只读凭据，记录实际消耗。

初始化脚本逐请求追加 `usage.ndjson`，在累计读取 195 万或写入 59 万时拒绝继续新操作，给最后一个请求及检查留余量。这是接近预算时停机复核的护栏，不是平台硬配额，也不覆盖其他人在同一库的操作。已提交但响应丢失的批次，恢复时按已测每批 `2N+3` 读取、`2N+1` 写入补记保守估算并标注；最终结合 Cloudflare 指标补核。

不要在已有基线目录覆盖聚合结果或将另一数据库的产物混入。导入中断后先检查保存的数据库 ID、水位和批次哈希，再重跑同一命令。发布后不得再次导入覆盖在线计数。回滚主站代码不会删除统计数据；若需停用功能，可将控制表 ready 置 0，并移除共现 cron，保留日志以便恢复。
